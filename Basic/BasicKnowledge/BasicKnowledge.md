面试里常把进程地址空间粗分成四区，细分成五区：

| 区域 | 存什么 | 生命周期 | 谁分配/释放 | 游戏里常踩的坑 |
| ---- | ------ | -------- | ----------- | -------------- |
| 代码区 | 指令，只读 | 整个程序 | 系统装入 | 别往代码区写 |
| 常量区 | 字符串字面量等 | 整个程序 | 编译期确定 | `"hello"` 这种不要 `delete` |
| 全局/静态区 | 全局变量、`static` 变量 | 整个程序 | 编译期确定，启动时初始化 | 静态对象构造顺序不确定 |
| 栈区 | 局部变量、函数参数、返回地址 | 函数调用期间 | 编译器自动 | 大数组、深递归容易爆栈 |
| 堆区 | `new` / `malloc` 出来的内存 | 直到手动释放 | 程序员 / 智能指针 | 泄漏、碎片、double free |

栈快、连续、大小有限（Windows 默认约 1MB）；堆灵活但有分配开销和碎片。客户端每帧都 `new` 小对象，比算法慢更常见。

==局部变量在栈上，`new` 出来的对象在堆上，指针变量本身可以在栈上，指向堆。==

#### 2. 内存分配

**2.0 如何描述一块内存？**

C++ 描述一块内存，核心就是 **地址 + 范围**；

那什么又是地址呢？地址就是内存里**某一字节的编号**——CPU 用这个编号去读写那一块存储。

比如一个int变量 

```c++
int a = 0;
//指针也是一个变量，存的是地址，且是虚拟地址
int *b = &a;
//比如&a = 0x100,而一个int类型占4个字节,所以a在内存中就是占用了0x100开始的4个字节
```

**2.1 什么是指针和引用，异同？**

上一个问题中指出，**指针是一个存储着地址的变量**，那它跟引用有何异同呢

**引用**是**变量的别名**

``` c++
int a = 0;
int& b = a;//b是a的别名
b = 20;	   //相当于a = 20;
int c = 0;
b = c;	   //并非改绑，只是把c的值赋值给a
---------------------------
int a;
int &b = a;//没有初始化a给a赋值，但是可以这么写，绑定了b是a的引用
```

```c++
int a = 0;
int* b = &a;//b指向的是a占的第一个字节的地址
int c = 0;
b = &c;
---------------------------
int a;
int* b = &a;//也是可以这么写的
```

***  和 & ** 在声明中都代表的是变量的类型

* int& b代表的是变量b的类型是int类型的引用
* int* b代表的是变量b的类型是int类型的指针

==指针和引用都是变量，但是指针是对象，引用不是对象==

|                            | 指针 `p`                               | 引用 `b`               |
| -------------------------- | -------------------------------------- | ---------------------- |
| 语言身份                   | 对象                                   | 不是对象，是别名       |
| 自己有没有“独立存储”的语义 | 有（存地址）                           | 没有                   |
| 操作作用在谁身上           | 可以操作指针本身，也可以 `*p` 操作目标 | 一律作用在绑定的对象上 |

**2.2 内存对齐**

内存对齐阐述的是数据在内存上的排布问题：数据的起始地址通常要是它**对齐值**的倍数。CPU 按字（4/8 字节）甚至按 cache line（常见 64 字节）去读内存，不对齐就要拆成多次访问，x86 还能忍，有的平台直接硬件异常。

**基本类型的对齐值一般等于自身大小**（`int` 4、`double` 8、指针 8）。结构体/类还要再套三条规则：

1. 每个成员的偏移必须是该成员对齐值的倍数，不够就在前面**填 padding**
2. 结构体自己的对齐值 = 成员里最大的那个对齐值
3. 结构体总大小必须是自身对齐值的倍数，尾部再填 padding

```c++
struct A {
    char  c;   // offset 0, 占 1
               // padding 3 字节
    int   i;   // offset 4, 占 4
};             // sizeof(A) = 8，对齐值 4

struct B {
    int   i;   // offset 0
    char  c;   // offset 4
               // padding 3
};             // sizeof(B) 也是 8，但排布不同

struct C {
    char  c;
    double d;  // 对齐 8，前面要填 7
    int   i;
};             // sizeof(C) = 24（尾部还要补齐到 8 的倍数）
```

调成员顺序往往就能缩小体积。`#pragma pack(1)` / `__attribute__((packed))` 可以强行紧凑，网络包、文件头常用，但访问可能变慢，有的 CPU 还会 trap。

游戏客户端为什么在意：

- 同步到 GPU 的 constant buffer、顶点格式有对齐要求
- 网络协议结构体乱 pack 会和服务器对不上
- 热路径上结构体太大，cache miss 比多算几次更疼

面试常追问：`sizeof` 空类是 1（要能取地址、放进数组）；有虚函数后对象头上多一个 `vptr`（64 位一般 8 字节）。

>sizeof(Empty) 按「里面有什么数据」来算应该是 0，但 C++ 不允许完整对象大小为 0，所以编译器塞 1 字节占位，只为了能取地址、能放进数组。



2.3 new/malloc，delete/free的用法，异同**

```c++
int* p1 = (int*)malloc(sizeof(int));  // 只拿生内存，不调构造
*p1 = 1;
free(p1);                             // 不调析构

int* p2 = new int(1);                 // 分配 + 构造
delete p2;                            // 析构 + 释放

int* arr = new int[10];
delete[] arr;                         // 数组必须配对 delete[]
```

| | `malloc` / `free` | `new` / `delete` |
| - | ----------------- | ---------------- |
| 所属 | C | C++ |
| 返回 | `void*`，要自己转类型 | 带类型的指针 |
| 构造/析构 | 不管 | `new` 调构造，`delete` 调析构 |
| 失败 | 返回 `nullptr` | 默认抛 `std::bad_alloc`（`nothrow` 版返回空） |
| 大小 | 自己算字节数，可 `realloc` | 编译器按类型算 |
| 能否重载 | 不能 | 可以重载 `operator new/delete` |

==绝对不要混用：`new` 配 `free`，`malloc` 配 `delete`，`new[]` 配 `delete`，都是未定义行为。==

再补三点面试爱问的：

- **`new` 实际两步**：先 `operator new` 拿内存，再在这块内存上调构造函数。`delete` 相反：先析构，再 `operator delete`。
- **placement new**：在已经有的内存上构造，对象池、内存池全靠它。

```c++
char buf[sizeof(T)];
T* p = new (buf) T(args);  // 不分配，只构造
p->~T();                   // 必须手动析构，不能 delete p
```

- 游戏里每帧 `new/delete` 很容易卡顿和碎片，常见做法是对象池 + placement new，或直接用栈上/预分配数组。

**2.4 智能指针是什么，怎么用，怎么实现？**

智能指针 = **用对象的析构函数自动释放资源**（RAII）。核心三个：

| | `unique_ptr` | `shared_ptr` | `weak_ptr` |
| - | ------------ | ------------ | ---------- |
| 所有权 | 独占 | 共享（引用计数） | 不拥有，只观察 |
| 拷贝 | 禁止，只能 move | 可以拷贝 | 可以拷贝 |
| 开销 | 几乎等于裸指针 | 原子加减计数 + 控制块 | 不增加 `use_count` |
| 典型用途 | 函数里临时资源、明确单主 | 多方共享同一资源 | 打破 `shared_ptr` 环 |

```c++
auto u = std::make_unique<Player>(id);     // 优先 make_xxx，异常安全
std::unique_ptr<Player> u2 = std::move(u); // u 变成空

auto s = std::make_shared<Player>(id);
std::weak_ptr<Player> w = s;
if (auto locked = w.lock()) {              // 还活着才能用
    locked->Update();
}
```

**循环引用**是 `shared_ptr` 经典坑：A 持有 B、B 持有 A，计数永远到不了 0。一边改成 `weak_ptr`。父子关系一般父 `unique_ptr`/`shared_ptr`、子回指用 `weak_ptr` 或裸指针。

面试手写 `unique_ptr` 骨架（拷贝禁掉，移动把指针偷走）：

```c++
template<typename T>
class UniquePtr {
    T* ptr;
public:
    explicit UniquePtr(T* p = nullptr) : ptr(p) {}
    ~UniquePtr() { delete ptr; }

    UniquePtr(const UniquePtr&) = delete;
    UniquePtr& operator=(const UniquePtr&) = delete;

    UniquePtr(UniquePtr&& other) noexcept : ptr(other.ptr) {
        other.ptr = nullptr;
    }
    UniquePtr& operator=(UniquePtr&& other) noexcept {
        if (this != &other) {
            delete ptr;
            ptr = other.ptr;
            other.ptr = nullptr;
        }
        return *this;
    }

    T& operator*()  const { return *ptr; }
    T* operator->() const { return ptr; }
    T* get()        const { return ptr; }
};
```

`shared_ptr` 实现要点：堆上另有一块**控制块**，里面至少有 `use_count`、`weak_count`、指向对象的指针。拷贝 `++use_count`，析构 `--use_count`，到 0 析构对象；`weak_count` 到 0 再释放控制块。`make_shared` 把对象和控制块一次分配，更缓存友好。

游戏客户端建议：**默认 `unique_ptr`，共享场景才 `shared_ptr`，热路径、粒子、子弹用对象池，不要成吨 `shared_ptr`。** Unity C# 没有这套，Unreal 用 `TUniquePtr` / `TSharedPtr` / `TWeakPtr`，思想一样。

**2.5 常见内存问题（客户端高频）**

- 野指针：释放后还在用。`delete` 后立刻置空；优先智能指针
- 悬空引用：引用绑定的对象已经死了。别返回局部变量的引用
- 内存泄漏：`new` 了没 `delete`，或异常路径跳过 `delete`。RAII 能挡大部分
- 栈溢出：递归太深、栈上开巨大数组。大 buffer 放堆上
- double free：同一块内存释放两次
- 浅拷贝：两个对象指向同一块堆内存，析构释放两次。有堆资源就要自己管拷贝/移动（三/五法则）

### 三、程序里有什么？

#### 1. 变量和常量

[C++变量与常量详解-CSDN博客](https://blog.csdn.net/xholes/article/details/68065358)

变量：一块能存储数据、并且带类型的内存。

常量：值固定、初始化后不能再改。分成**字面量**（`42`、`"hi"`）和 **`const` / `constexpr` 修饰的常量**。

**1.1 变量的定义和声明，`extern` 怎么实现？**

- **声明**：告诉编译器“有这么个名字、是这个类型”，可以出现多次
- **定义**：真正分配存储，整个程序里只能有一次（ODR）

```c++
// a.cpp
int g_hp = 100;          // 定义：分配内存并初始化

// a.h
extern int g_hp;         // 声明：不分配，只是说“别处有个 int g_hp”

// b.cpp
#include "a.h"
void Hurt() { g_hp -= 10; }  // 链接阶段把所有对 g_hp 的引用接到 a.cpp 那一块内存
```

`extern` 的实现就是**链接**：编译器在 `.o` 里给未定义的符号留个重定位入口，链接器在别的目标文件里找到唯一的定义，把地址填回去。找不到就 `undefined reference`，找到两个就 `multiple definition`。

`const` 全局默认内部链接（每个 .cpp 一份），要跨文件共享得写成 `extern const int kMax = 10;` 并在头文件里 `extern const int kMax;`。C++17 后更常见的是头文件里 `inline constexpr int kMax = 10;`。

**1.2 `static` 的三种身份（面试必分清）**

| 写在哪 | 含义 |
| ------ | ---- |
| 局部变量前 | 静态局部：只初始化一次，生命周期到程序结束，作用域仍在函数内 |
| 全局 / 命名空间 / 文件作用域 | 内部链接：这个名字只在本翻译单元可见 |
| 类成员 | 属于类本身，所有对象共享一份；`static` 函数没有 `this` |

```c++
void Foo() {
    static int n = 0;   // 第一次进来才初始化
    ++n;
}
```

**1.3 `const` / `constexpr` / 指针与 const**

- `const`：运行时也不许改（通过这个名字）
- `constexpr`：编译期就能算出来，更能当数组长度、模板参数
- 读声明从右往左：

```c++
const int* p;        // 指向 const int 的指针，*p 不能改，p 能改
int* const p;        // 指针本身 const，不能改指向，*p 能改
const int* const p;  // 都不能改
```

成员函数后的 `const` 表示不改 `*this`，const 对象只能调 const 成员函数。

#### 2. 函数

**2.1 传值、传引用、传指针**

- 传值：拷贝一份，改形参不影响实参；大对象贵
- 传引用：别名，无拷贝；只读用 `const T&`
- 传指针：可以传空，可以指向数组；语义是“可选 + 可改”

游戏里读配置、读组件：`const T&`；要表示“可能没有”：指针或 `optional`。

**2.2 重载、默认参数、内联**

- 重载看**参数列表**（个数、类型、const、引用），不看返回值
- 默认参数只在声明里写一次，从右往左缺省
- `inline` 是给链接器用的“允许多个定义”，现编译器自己决定是否真内联。头文件里的函数模板、类内定义默认就是 inline

**2.3 函数指针与 lambda**

```c++
void (*cb)(int) = [](int x) { /* ... */ };  // 无捕获的 lambda 能转函数指针
auto f = [id](float dt) { Update(id, dt); }; // 有捕获就是闭包对象
```

客户端定时器、输入绑定、UI 回调到处都是。有捕获用 `std::function` 或自己做委托，注意 `std::function` 有分配开销。

#### 3. 类与对象

**3.1 对象里到底有什么**

成员变量按声明顺序排布（受对齐影响）；成员函数不占对象空间，代码在代码区。虚函数会在对象开头（常见实现）放一个 `vptr`。

**3.2 六大特殊成员函数**

编译器可能隐式生成：默认构造、析构、拷贝构造、拷贝赋值、移动构造、移动赋值。

有堆资源时走 **三法则 / 五法则**：你写了析构、拷贝构造、拷贝赋值之一，另外几个也要自己管（或 `= delete`）。有自定义拷贝通常也要定义移动，或明确删除。

```c++
class Buffer {
    char* data;
    size_t size;
public:
    Buffer(const Buffer& o);            // 深拷贝
    Buffer& operator=(const Buffer& o);
    Buffer(Buffer&& o) noexcept;        // 偷指针，o.data = nullptr
    Buffer& operator=(Buffer&& o) noexcept;
    ~Buffer() { delete[] data; }
};
```

**浅拷贝 vs 深拷贝**：默认按字节/按成员拷，指针只拷地址；两个对象析构会 double free。深拷贝是新分配一块再抄内容。移动则是把资源所有权转走，适合返回值、容器扩容。

**3.3 RAII**

资源获取即初始化：构造里拿到（内存、文件、锁、句柄），析构里释放。智能指针、`lock_guard`、`FScopeLock`（UE）都是它。异常或提前 `return` 也能释放，这是客户端防止泄漏的第一原则。

**3.4 `this`、初始化列表、初始化顺序**

- `this` 是指向当前对象的指针，成员函数被编译成带隐藏参数 `T* this`
- 成员**按声明顺序**初始化，不是按初始化列表的书写顺序
- 引用成员、const 成员、没有默认构造的成员，必须用初始化列表

#### 4. 面向对象：继承、虚函数、多态

**4.1 三种继承**

| | public 继承 | protected 继承 | private 继承 |
| - | ----------- | -------------- | ------------ |
| 语义 | is-a | 少用 | 实现继承（has-a 的一种） |
| 基类 public 到派生类 | public | protected | private |

游戏里实体继承链不要太深，组合（组件）比七层 `Player : Role : Character : Actor : ...` 好维护。

**4.2 虚函数与虚表**

没有 `virtual`：看指针的**静态类型**调用，编译期就定了（静态绑定）。

有 `virtual`：看对象的**真实类型**调用（动态绑定）。常见实现：

1. 类有一张 **vtable**，每个虚函数一个函数指针
2. 每个对象有一个 **vptr** 指向自己类的 vtable
3. 调用 `p->Update()` ≈ `p->vptr[i](p)`

```c++
struct Actor {
    virtual void Update() { }
    virtual ~Actor() { }     // 基类析构必须虚，否则 delete 基类指针不会调派生析构
};
struct Player : Actor {
    void Update() override { }
};
```

面试常画：

```
Player 对象
┌──────────┐
│  vptr    │ ──► Player 的 vtable ──► Player::Update
│  成员... │                          Player::~Player
└──────────┘
```

多重继承会有多个 vptr，还可能有虚基类（菱形继承用 `virtual public`），对象布局更复杂，客户端项目一般能避开就避开。

**4.3 纯虚函数 / 抽象类 / 接口**

```c++
struct IUpdatable {
    virtual void Update(float dt) = 0;
    virtual ~IUpdatable() = default;
};
```

不能实例化。适合系统接口：输入、技能、AI 状态。

**4.4 对象切片**

```c++
Player p;
Actor  a = p;   // 只拷了 Actor 那部分，虚表也变成 Actor 的
```

多态必须用**指针或引用**，不要按值传基类。

#### 5. 左值、右值与移动语义

- 左值：有身份、能取地址，如变量 `x`
- 右值：即将结束的临时量，如 `Foo()` 的返回值、`std::move(x)` 之后的那个

`T&&` 是右值引用，用来接临时对象，把资源偷过来而不是深拷贝。`std::move` **不移动任何东西**，只是把类型转成右值引用，告诉对方“可以偷”。

容器 `push_back` 临时对象、函数返回局部对象，靠的就是移动。游戏里大资源（网格、贴图句柄包装类）实现移动构造，能少很多次分配。

### 四、容器

STL 容器是面试必考，客户端热路径还要知道它**会不会堆分配、迭代器会不会失效**。

#### 1. 序列容器怎么选

| 容器 | 底层 | 随机访问 | 头尾插入 | 中间插入 | 迭代器失效 |
| ---- | ---- | -------- | -------- | -------- | ---------- |
| `vector` | 一块连续内存 | O(1) | 尾部均摊 O(1) | O(n) | 扩容时全部失效；中间插入，其后失效 |
| `deque` | 分块 + 中控 | O(1) | 两端 O(1) | O(n) | 插入删除使部分失效 |
| `list` | 双向链表 | 不支持 | O(1) | 已知位置 O(1) | 只有被删节点失效 |
| `array` | 栈上定长 | O(1) | 不能动态插 | — | 不涉及堆 |
| `string` | 类似 vector\<char\> | O(1) | 尾部均摊 O(1) | O(n) | 类似 vector |

==默认用 `vector`。== 只有频繁在中间塞删、且不需要随机访问，才考虑 `list`。`list` 每个节点一次分配，cache 极差，游戏里很少是对的选择。

**`vector` 必问：**

- `size` 是当前元素个数，`capacity` 是已分配空间
- 空间不够就扩容（常见 1.5x / 2x）：新分配 → 移动/拷贝旧元素 → 释放旧块
- `reserve(n)` 预分配，避免战斗中途扩容卡帧
- `resize` 会构造新元素；`clear` 只把 size 置 0，capacity 往往还在
- 下标 `[]` 不检查，`at()` 越界抛异常

```c++
std::vector<Enemy> enemies;
enemies.reserve(256);          // 对象池/预分配思想
enemies.emplace_back(pos);     // 直接在尾部构造，少一次移动
```

#### 2. 关联容器怎么选

| 容器 | 底层 | 查找/插入 | 有序 | 说明 |
| ---- | ---- | --------- | ---- | ---- |
| `map` / `set` | 红黑树 | O(log n) | 按 key 有序 | 需要顺序、范围查询时用 |
| `unordered_map` / `unordered_set` | 哈希桶 | 均摊 O(1)，最坏 O(n) | 无序 | 要有哈希函数；rehash 时迭代器全失效 |
| `multimap` / `multiset` | 红黑树 | O(log n) | 有序 | 允许重复 key |

客户端：实体 ID → 指针，配置表 ID → 数据，默认 `unordered_map`。要按 ID 遍历、或做范围，用 `map`。自定义类型当 key，必须提供 `operator==` 和哈希（unordered）或 `operator<`（map）。

哈希冲突：链地址（libstdc++）或开放寻址。负载因子过高会 rehash，一次性分配和搬迁，可能卡帧——可以 `reserve`。

#### 3. 适配器

`stack` / `queue` / `priority_queue` 是适配器，默认底层分别是 `deque`、`deque`、`vector`+堆。`priority_queue` 就是堆，AI 寻路开放列表、伤害数字、定时器都能用。

#### 4. 迭代器与算法

- 迭代器像泛化的指针：`begin` / `end`，`++`，`*`
- `vector` 随机访问迭代器，`list` 双向，`forward_list` 单向
- `<algorithm>`：`sort`、`find`、`lower_bound`、`remove_if` + `erase`（erase-remove 惯用法）

```c++
auto it = std::remove_if(v.begin(), v.end(), [](const Enemy& e) {
    return e.dead;
});
v.erase(it, v.end());   // remove_if 只是把要留的搬到前面
```

遍历 `vector` 时 `push_back` 可能导致迭代器、引用、指针全部失效——这是客户端崩溃高频原因。

## 2. 动手学操作系统

客户端不是写内核，但面试会拿 OS 概念问你：**进程/线程、同步、内存**。游戏里对应的是主线程、渲染线程、任务队列、卡顿和崩溃。

### 一、进程管理

#### 1. 进程和线程

- **进程**：资源分配单位。自己的虚拟地址空间、句柄表、一份代码 + 数据。进程间默认隔离
- **线程**：调度单位。同进程线程共享地址空间和文件，各自有栈、寄存器、线程局部存储（TLS）

游戏一般是**一个进程、多线程**：主逻辑、渲染、资源加载、网络收发、音频。Unity 主线程跑脚本，Job System / 自己的线程池做并行；UE 有 GameThread、RenderThread、RHI thread。

| | 进程 | 线程 |
| - | ---- | ---- |
| 创建代价 | 高（要建地址空间） | 低 |
| 通信 | 管道、socket、共享内存，要序列化/同步 | 直接读写同一块内存，必须加锁或无锁 |
| 崩溃影响 | 一个进程挂了别的还在 | 一个线程野指针，整个进程可能没 |
| 切换 | 要切页表等，贵 | 轻一些 |

#### 2. 进程状态与调度

就绪 → 运行 → 阻塞（等锁、等 IO、等 vsync）→ 再就绪。CPU 调度算法面试常问：FCFS、短作业优先、时间片轮转、优先级、多级反馈队列。抢占 vs 非抢占。

游戏关心的不是算法名字，而是：

- **时间片内尽量把这一帧算完**，逻辑帧和渲染帧可以分开
- 线程优先级：音频、渲染别被后台加载抢走
- 避免在主线程做 IO、等锁，这是卡顿来源

#### 3. 同步与互斥

多线程共享数据就要同步，否则数据竞争，C++ 里是未定义行为。

| 工具 | 作用 | 注意 |
| ---- | ---- | ---- |
| `mutex` / 临界区 | 互斥，同时只有一个线程进临界区 | 持锁时间要短，别在锁里做 IO、调脚本 |
| `lock_guard` / `unique_lock` | RAII 加锁 | 防止中途 return 没解锁 |
| `recursive_mutex` | 同一线程可重入 | 能不用就不用，容易掩盖设计问题 |
| `condition_variable` | 等条件（队列不空、这一帧可以跑） | 要和 mutex 一起用，注意虚假唤醒 |
| `atomic` | 单个变量无锁读写 | 只保证这一次操作原子，不能替代复杂临界区 |
| 信号量 | 控制同时进入的数量 | 生产者-消费者 |
| 读写锁 | 读多写少 | 配置表热加载可以考虑 |

**死锁四个条件**（同时满足才会）：互斥、占有且等待、不可剥夺、循环等待。

预防：统一加锁顺序；用 `std::lock` 一次锁多个；超时；尽量少锁、缩小锁范围。客户端典型死锁：主线程等渲染锁，渲染线程等主线程的资源锁。

**线程安全单例**面试也爱问：C++11 后函数内 `static` 局部变量初始化是线程安全的（Magic Static）。

```c++
Config& GetConfig() {
    static Config inst;  // 第一次调用时构造，并发安全
    return inst;
}
```

游戏里单例仍要小心生命周期和解耦，见第 5 章。

### 二、作业管理

教材里的“作业”是用户提交的一批计算任务：作业调度（高级调度）决定哪些作业进入内存成为进程，进程调度（低级调度）决定哪个进程占 CPU。中级调度还会把进程换出到磁盘。

客户端可以这样对应：

- **一帧要做的工作** = 一堆 job（动画、物理、裁剪、粒子）
- **Job System / 任务队列** = 作业调度：把任务切成可并行的小块丢给 worker
- **依赖**：物理依赖动画、渲染依赖 cull 结果，用依赖图，不要瞎并行
- Unity `IJob` / `JobHandle.Complete()`、UE TaskGraph，都是这件事

面试若问作业调度 vs 进程调度：前者管“谁进内存”，后者管“谁上 CPU”；游戏 Job System 更接近“用户态任务调度”。

### 三、内存管理（OS 视角）

和 C++ 堆栈不是同一层：这里问的是**虚拟内存**。

#### 1. 虚拟地址 → 物理地址

每个进程一份虚拟地址空间，通过页表（多级）映射到物理页。CPU 有 **TLB** 缓存最近的翻译。缺页：页不在内存，OS 去磁盘（或文件映射）调页，游戏里这就是**卡一下**。

页大小常见 4KB，大页 2MB。资源、内存池按页对齐有时能少 TLB miss。

#### 2. 为什么要虚拟内存

- 进程隔离，A 写野指针不一定直接改到 B
- 看起来有连续大内存，物理上可以不连续
- 用磁盘换出冷页，物理内存不够时还能跑（但游戏一旦 swap 就掉帧，主机/手游往往宁可 OOM）

#### 3. 局部性与缓存

- 时间局部性：刚用过的还用（循环变量、当前技能配置）
- 空间局部性：附近的还会用（数组、结构体顺序遍历）

所以 `vector` 比 `list` 快，AoS vs SoA、对象池连续分配，都是在喂 cache。cache line 一般 64B，多线程写同一行不同变量会 **false sharing**。

#### 4. 堆分配器（进阶，大厂爱问）

`malloc` 底层一般有空闲链表、分 size class 的 slab、mmap 大块。游戏引擎常自研：

- **帧分配器 / 线性分配器**：这一帧从头 bump，帧末一次性清空，适合临时数据
- **对象池**：同尺寸对象复用，子弹、伤害数字
- **栈式分配器**：成对 push/pop

面试能说到“减少运行时向 OS 要页、减少碎片、提高局部性”就够用。

## 3. 动手学计算机网络

游戏客户端面试，网络几乎必问：**TCP 还是 UDP、怎么可靠、延迟怎么藏。**

### 一、协议栈（能画图就行）

应用层（自己的协议、HTTP、WebSocket）→ 传输层（TCP/UDP）→ 网络层（IP）→ 链路/物理。

IP 负责把包送到主机，TCP/UDP 负责端口、传到进程。

### 二、TCP vs UDP（客户端核心题）

| | TCP | UDP |
| - | --- | --- |
| 连接 | 需要连接 | 无连接 |
| 可靠 | 确认、重传、有序、流量/拥塞控制 | 尽最大努力，丢了就丢 |
| 延迟 | 丢包时头阻塞，RTT 可能被抬高 | 每个包独立，适合实时 |
| 头部 | 大 | 8 字节，小 |
| 典型 | 登录、商城、补丁、聊天可靠通道 | 帧同步/状态同步的位置、射击 |

很多游戏 **登录走 TCP/HTTP，战斗走 UDP**。UDP 之上自己做：序号、ACK、选择性重传、心跳。

**TCP 三次握手**：SYN → SYN+ACK → ACK，两边确认初始序号，连接建立。

**四次挥手**：FIN → ACK → FIN → ACK。中间可能 TIME_WAIT。面试能讲清“为什么是三次/四次、TIME_WAIT 干什么”即可。

**粘包 / 拆包**：TCP 是字节流，没有消息边界。应用层要自己定长度（包头 2/4 字节长度 + body）或分隔符。UDP 按数据报，一次 recv 一个包，但会丢、会乱序、会重复。

**拥塞控制**（慢启动、拥塞避免、快重传）让 TCP 丢包后主动降速——对实时对战不友好，这也是战斗常用 UDP 的原因。

### 三、可靠 UDP 要补什么

自己当“迷你 TCP”，但按消息类型区别对待：

- **必须可靠有序**：技能释放、开箱、交易（序号 + ACK + 重传）
- **必须可靠但可乱序**：部分事件
- **最新即可**：位置、朝向，丢了就丢，来新的覆盖旧的（snapshot / 状态同步）
- **冗余发送**：关键输入连续带上最近几帧（帧同步常见）

KCP、ENet、RakNet 都是这条路。面试不要求背源码，要说得出：**按业务拆通道，别让位置更新去等一个丢了的聊天包。**

### 四、客户端同步常见模型

- **锁步帧同步**：各方输入一致，逻辑确定。带宽小，延迟敏感，要等输入，卡一个人全员卡。MOBA、部分 RTS、部分格斗
- **状态同步**：服务器权威，定期下发快照。客户端做 **预测（本地先跑）+ 和解（服务器结果纠偏）+ 插值（别人平滑）**。MMO、射击常见
- **延迟隐藏**：客户端预测、动画先行、lag compensation（服务器倒带验证射击）

HTTP/HTTPS 用来拉配置、公告、支付；长连接用 TCP 或 WebSocket 做大厅。

### 五、其它常问

- `127.0.0.1` vs 局域网 IP vs 公网；NAT 打洞为什么难（对称 NAT）
- 字节序：网络大端，主机 x86 小端，协议里整数要约定
- 序列化：protobuf / 自定义二进制，注意对齐和版本兼容（加字段别把老包打崩）
- 安全：客户端不可信，伤害、掉落、货币校验在服务器

## 4. 动手学数据结构与算法

刷题放在 `Algorithm/DailyQuestion.md`。这里只记**面试能讲清楚、游戏里用得上**的结构。

### 一、复杂度

- 时间：最坏 / 平均；空间：额外内存
- `O(1)` `O(log n)` `O(n)` `O(n log n)` `O(n²)`
- 客户端：n 是这一帧的敌人数量、格子数，常数和 cache 往往比渐近符号更重要，但大厂笔试仍考标准写法

### 二、线性结构

- **数组 / vector**：连续、随机访问 O(1)，插入删除 O(n)。技能列表、这一帧要渲染的对象
- **链表**：插入 O(1)，查找 O(n)，cache 差。很少当主容器
- **栈**：匹配、撤销、DFS、UI 界面栈
- **队列**：BFS、消息队列、加载任务
- **双端队列**：两端进出
- **哈希表**：ID 查实体、配置。均摊 O(1)，最坏退化；字符串 key 注意哈希开销

### 三、树与堆

- **二叉搜索树 / 红黑树**：有序、O(log n)，就是 `map`
- **堆（优先队列）**：每次取最值 O(log n)。A* 开放列表、倒计时、伤害飘字按时间弹出
- **字典树 Trie**：敏感词、命令补全
- **四叉树 / 八叉树 / BVH**：空间划分，做范围查询、碰撞粗测、裁剪。开放世界、子弹多时比全量两两检测现实得多
- **并查集**：连通性，少见但笔试爱出

### 四、图与寻路（客户端高频）

- 图：邻接表为主
- BFS：无权最短（格子地图）
- Dijkstra / 堆优化：有权
- **A\***：Dijkstra + 启发（曼哈顿 / 欧氏），游戏寻路默认答案
- 导航网格 NavMesh：三角形上走，而不是纯格子
- 分层、路点、JPS：大地图优化

确定性：帧同步项目里寻路结果必须各端一致，浮点要小心。

### 五、常考算法模板（和刷题互补）

- 双指针、滑动窗口
- 二分（有序、单调性）
- 前缀和、差分
- 排序：快排思想、堆排、归并（稳定）、`std::sort` 是内省排序
- 回溯、DFS/BFS
- 动态规划：背包、最长子序列（笔试）；客户端业务里更多是状态机而不是 DP
- 位运算：状态压缩、flag 枚举（见每日一题里的 mask）

## 5. 浅析设计模式

参考来自：[游戏编程模式](https://gpp.tkchu.me/)

GOF 23 种不必背完。游戏客户端面试更常问下面这些，而且最好能结合项目讲。

### 一、架构向

**Game Loop**

`while (running) { 处理输入; 更新逻辑(dt); 渲染; }`  
固定逻辑帧 + 渲染追帧（accumulator）能避免物理和帧率绑死。Unity 的 `Update` / `FixedUpdate` 就是这个拆法。

**Update Method**

每个实体一个 `Update(dt)`，循环调用。简单直接；实体一多、依赖一乱就痛苦。后面往往拆成系统和组件。

**Component / ECS 思想**

不搞很深的继承：`Player` 是一堆组件（移动、血量、技能、动画）的容器。Unity `MonoBehaviour`、UE Actor+Component 都是。优点是组合复用；坑是组件间通信和执行顺序。

**Singleton**

全局唯一：音频、输入、配置。实现简单，生命周期和测试差，到处耦合。能注入、能当子系统就别新堆单例。C++11 函数内 static 是线程安全写法，见操作系统章。

### 二、行为向

**State**

角色：待机 / 跑 / 跳 / 技能 / 受击。当前状态对象处理输入和切换，避免满屏 `if (state == ...)`。动画状态机是亲戚。

**Command**

把“输入”做成对象：`JumpCommand`、`FireCommand`。好处：可以延迟执行、回放、撤销、网络转发（帧同步就是每帧一串 command）。

**Observer / 事件**

UI 监听玩家血量、成就监听击杀。解耦；坑是生命周期（忘记取消订阅变成野回调）和事件风暴。C# event、UE delegate、自己写的 EventBus 都是。

**Strategy / 策略**

寻路、瞄准、移动插值可替换。AI 换行为不一定要换整个类。

### 三、性能向（客户端加分项）

**Object Pool**

预创建 N 个子弹，用的时候激活，不用的时候还回去，避免运行时 `new`/`Instantiate`。和 placement new、内存池是一层思想。

**Flyweight**

共享不变数据：一千棵树共用一份网格和材质，实例只存位置。GPU instancing 是硬件版享元。

**Dirty Flag**

世界矩阵、UI 布局：变了才重算，否则用缓存。Transform 层级更新常用。

**Spatial Partition**

四叉树、网格、BVH，见算法章。碰撞和 AOI（感兴趣区域）都靠它。

**Data Locality**

把每帧一起遍历的数据放连续：数组、SoA、ECS 的 chunk。比换个更花哨的算法更能提帧。

### 四、其它会提到的

- **Prototype**：用原型克隆敌人，而不是一堆子类
- **Factory / Builder**：根据配置 ID 创建技能、UI、实体
- **Bytecode / 数据驱动**：技能、副本用表或脚本配置，少写死 if
- **Subclass Sandbox**：基类提供 `PlaySound`、`Spawn`，子类技能只拼流程
- **Type Object**：怪物类型是数据对象，不是每个怪物一个 C++ 类

面试话术：**先说解决什么问题，再说不用它会怎样，再落到项目里哪一块。** 空背类图不如讲“子弹池少了 Instantiate 卡顿”、“技能用 Command 方便录像”。

### 附录：游戏客户端面试怎么串起来

同一件事会在不同章出现，串起来才像做过项目：

1. 一帧：Game Loop → 多线程 Job → 尽量别在主线程 `new` 和 IO
2. 实体：组件 + `vector` 连续存放 → 对象池 → 对齐和 cache
3. 技能/输入：Command + 状态机 → 网络发送 → TCP/UDP 分通道
4. 资源：智能指针/句柄 + RAII → 异步加载别阻塞渲染
5. 崩溃：野指针、迭代器失效、死锁、对象切片，全是前面那些规则没守住

C++ 语法用 studycpp / learncpp 往下补；算法用每日一题练手；模式结合自己项目讲故事。
